## Purpose and first route through the repo

CHIP is a proof-of-concept health and federal-funding exploration app for analysts and demo users. It maps published area indicators, offers area profiles, and explores CDC funding. It is not a unified, fully automated federal-data catalog. Start with [README](../README.md) for local setup, [backend routes](../backend/app/main.py), [main map](../frontend/src/App.jsx), [shared area UI](../frontend/src/pages/Places2025Pilot.jsx), [area registry](../backend/app/area_pilot/registry/), [migrations](../backend/alembic/versions/), and the [action diary](PROJECT_DIARY.md). The audit predates the AHRF, CLH, and EPA AQI implementations and must not be used as a current publication list.

## Shared area lifecycle and storage

**Verified 2026-11-14T16:04:41Z; EPA AQI added 2026-11-14T16:48Z: code, registries, database pointers.** Shared area products are PLACES 2025, ACS 2020–2024 B19013, HRSA AHRF 2024–2025, AHRQ CLH 2023, and EPA AirData annual AQI by county 2025. Product JSON registries in [area_pilot/registry](../backend/app/area_pilot/registry/) define source/release labels, supported geographies, measures, periods, missingness, boundary vintage, and `auto_publish: false`. They are curated configuration, not a live source-discovery service. [Area source adapters](../backend/app/area_pilot/) fetch official APIs or archives into `data/ingest/<product>/<run UUID>/`, preserve original bytes and SHA-256 provenance in `area_pilot.source_file`, and stage source-specific rows. Validation checks schema, definitions, keys, geography joins, statuses, and read-model parity. `review` rechecks retained evidence; `approve-publish` requires the exact reviewed semantic, schema, and metadata digests and moves only that product's `area_pilot.active_release` pointer transactionally. Identical content records a duplicate run. Changed same-label content or unsupported changes are held for review. `rollback` selects a retained published release; first-release `deactivate` hides that product. Published rows remain queryable by release ID. No archive deletion is automatic. Read the relevant [PLACES](../backend/docs/chip_places_2025_pilot.md), [ACS](../backend/docs/chip_acs5_2024_phase3.md), [AHRF](../backend/docs/chip_ahrf_2024_2025.md), [CLH](../backend/docs/chip_clh_2023_curated.md), [EPA AQI](../backend/docs/chip_epa_aqi_county_2025.md), and [operations](../backend/docs/chip_area_phase4_operations.md) guides before changing state.

`area_pilot.release`, `active_release`, `run`, `source_file`, `validation`, staging tables, and product-specific observation/boundary tables are created by [area migrations](../backend/alembic/versions/). The shared API is [router.py](../backend/app/area_pilot/router.py) at external `/api/area/{catalog,map,legend,table}`; each request selects an explicit dataset, published release, measure, period, population, value type, geography, and bounding box. The API enforces a 5,000-feature viewport cap and returns 413 for overwide requests. The frontend resolves the active release from the catalog and includes it in cache keys and requests; table pagination is capped at 500 rows. There is no persistent tile cache. `data/ingest` is an evidence archive, not a disposable build cache.

Legacy PLACES, ACS non-medical-factor, SVI, HPSA, CMS, FEMA, and USDA integrations use their own importers and tables. They generally upsert or replace rows and do **not** acquire shared immutable release pointers merely because they appear in the same UI. CDC funding, TAGGS, USAspending, profiles, classification, and models are specialized financial workflows with different attribution and aggregation rules; [funding ingestion](../backend/docs/cdc_funding_source_ingestion.md) already has its own hashes and fiscal-year replacement process. Do not route funding through the shared area observation contract by assumption.

## Map and interpretation contract

**Verified 2026-11-14: current routes, registries, and product guides.** The new area page starts at a broad published level and follows product availability: ACS state→county→tract; PLACES county→tract; CLH county→tract for three measures and county only for two; AHRF and EPA AQI county only. EPA AQI returns every 2024 boundary county in the viewport. Counties without an EPA summary come back as `no_reported_value`, computed at read time and never stored. The product uses fixed neutral legend breaks, not daily AQI health-category colors, and reports Days with AQI for every county that has a value. Tract switching is around zoom 10. Unsupported levels retain a supported level with an explanation; no county/state estimate is synthesized from child areas. Every area map, legend, and table uses the same published release and selection. Product-specific missing/`not_published`/`open_ended` statuses, numeric zero, PLACES 95% intervals, ACS 90% MOE, and absent uncertainty must remain distinct. Read product registries and guides before changing a legend. Legacy [main map](../frontend/src/App.jsx) has separate source-specific transitions and caches, including a 10-minute in-memory TTL, request aborts, and in-flight deduplication; its behavior is not the shared area contract. Its geospatial joins can differ from the newer isolated 2024 boundaries.

## Durable decisions and next work

Keep an independent active pointer per shared product so failed refresh or rollback cannot switch another product. Use source-published county/state values instead of aggregating child values, especially for medians, scores, ranks, and prevalence. Join only compatible boundary vintages; isolate 2024 and CT special boundaries instead of rewriting legacy shapes. Preserve source-specific status, uncertainty, and attribution.
