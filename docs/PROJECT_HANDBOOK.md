## Purpose and first route through the repo

CHIP is a proof-of-concept health and federal-funding exploration app for analysts and demo users. It maps published area indicators, offers area profiles, overlays HRSA health center service-site points, EPA TRI reporting facilities, and CMS nursing homes on area maps, maps CMS Original Medicare Geographic Variation at state and county level and USDA Food Environment Atlas county measures, and explores CDC funding. The **staging beta** opens with place search and a cited county profile; the live demo still opens on the pre-beta map. It is not a unified, fully automated federal-data catalog. Start with [README](../README.md) for local setup, [community API](../backend/app/community/router.py), [community pages](../frontend/src/community/), [shared area UI](../frontend/src/pages/Places2025Pilot.jsx), [area registry](../backend/app/area_pilot/registry/), [migrations](../backend/alembic/versions/), and the [action diary](PROJECT_DIARY.md). The [source inventory](../backend/docs/chip_source_inventory.csv) now has 99 records after the staging ACS community addition; the [November 13 audit](../backend/docs/chip_federal_data_current_state_audit.md) is a historical candidate inventory and must not be used as a current publication list.

## Shared area lifecycle and storage

**Verified 2026-11-14T16:04:41Z; EPA AQI added 2026-11-14T16:48Z: code, registries, database pointers.** Shared area products are PLACES 2025, ACS 2020–2024 B19013, HRSA AHRF 2024–2025, AHRQ CLH 2023, EPA AirData annual AQI by county 2025, CMS Original Medicare Geographic Variation 2024 (state and county; `area_pilot.stage_cms_gv`, `observation_cms_gv`; [guide](../backend/docs/chip_cms_om_geographic_variation.md)), and USDA ERS Food Environment Atlas July 2025, five county measures (`area_pilot.stage_usda_fea`, `observation_usda_fea`; [guide](../backend/docs/chip_usda_food_environment_atlas.md)). Product JSON registries in [area_pilot/registry](../backend/app/area_pilot/registry/) define source/release labels, supported geographies, measures, periods, missingness, boundary vintage, and `auto_publish: false`. They are curated configuration, not a live source-discovery service. [Area source adapters](../backend/app/area_pilot/) fetch official APIs or archives into `data/ingest/<product>/<run UUID>/`, preserve original bytes and SHA-256 provenance in `area_pilot.source_file`, and stage source-specific rows. Validation checks schema, definitions, keys, geography joins, statuses, and read-model parity. `review` rechecks retained evidence; `approve-publish` requires the exact reviewed semantic, schema, and metadata digests and moves only that product's `area_pilot.active_release` pointer transactionally. Identical content records a duplicate run. Changed same-label content or unsupported changes are held for review. `rollback` selects a retained published release; first-release `deactivate` hides that product. Published rows remain queryable by release ID. No archive deletion is automatic. CMS Nursing Home Provider Information adds an independent point release and pointer, with staged original CSV rows and typed nursing-home points; see its operator guide. **Point products** reuse the same release, run, source-file, validation, review, and pointer tables but store sites in product-specific point tables, never in area observation tables: HRSA health center sites use `area_pilot.stage_hrsa_site` (raw rows) and `area_pilot.site_hrsa` (`geometry(Point,4326)`, explicit `location_status`, published-release immutability trigger) with the protected read API `/api/area/sites/{catalog,map,table,detail}` ([guide](../backend/docs/chip_hrsa_health_center_sites.md)). EPA TRI reporting facilities (`epa_tri_facilities`) keep one row per Form R/Form A submission in `area_pilot.stage_tri_report` (raw) and `tri_report` (typed, no quantities), one row per TRIFD in `tri_facility` (point, explicit `location_status`, spatially derived county kept apart from the reported county), every chemical ID in `tri_chemical`, and (facility, chemical) relationships in `tri_facility_chemical`; protected API `/api/area/tri/{catalog,map,table,detail,chemicals}` ([guide](../backend/docs/chip_epa_tri_facilities.md)). Read the relevant [PLACES](../backend/docs/chip_places_2025_pilot.md), [ACS](../backend/docs/chip_acs5_2024_phase3.md), [AHRF](../backend/docs/chip_ahrf_2024_2025.md), [CLH](../backend/docs/chip_clh_2023_curated.md), [EPA AQI](../backend/docs/chip_epa_aqi_county_2025.md), and [operations](../backend/docs/chip_area_phase4_operations.md) guides before changing state.

`area_pilot.release`, `active_release`, `run`, `source_file`, `validation`, staging tables, and product-specific observation/boundary tables are created by [area migrations](../backend/alembic/versions/). The shared API is [router.py](../backend/app/area_pilot/router.py) at external `/api/area/{catalog,map,legend,table}`; each request selects an explicit dataset, published release, measure, period, population, value type, geography, and bounding box. The API enforces a 5,000-feature viewport cap and returns 413 for overwide requests. The frontend resolves the active release from the catalog and includes it in cache keys and requests; table pagination is capped at 500 rows. There is no persistent tile cache. `data/ingest` is an evidence archive, not a disposable build cache.

Legacy PLACES, ACS non-medical-factor, SVI, HPSA, CMS, FEMA, and USDA integrations use their own importers and tables. They generally upsert or replace rows and do **not** acquire shared immutable release pointers merely because they appear in the same UI. CDC funding, TAGGS, USAspending, profiles, classification, and models are specialized financial workflows with different attribution and aggregation rules; [funding ingestion](../backend/docs/cdc_funding_source_ingestion.md) already has its own hashes and fiscal-year replacement process. Do not route funding through the shared area observation contract by assumption.

## Map and interpretation contract

**Verified 2026-11-14: current routes, registries, and product guides.** The new area page starts at a broad published level and follows product availability: ACS state→county→tract; CMS OM GV state→county (zoom 6, no tracts); PLACES county→tract; CLH county→tract for three measures and county only for two; AHRF, EPA AQI, and USDA FEA county only. EPA AQI returns every 2024 boundary county in the viewport. Counties without an EPA summary come back as `no_reported_value`, computed at read time and never stored. The product uses fixed neutral legend breaks, not daily AQI health-category colors, and reports Days with AQI for every county that has a value. Tract switching is around zoom 10. Unsupported levels retain a supported level with an explanation; no county/state estimate is synthesized from child areas. Every area map, legend, and table uses the same published release and selection. Product-specific missing/`not_published`/`open_ended` statuses, numeric zero, PLACES 95% intervals, ACS 90% MOE, and absent uncertainty must remain distinct. Read product registries and guides before changing a legend. The optional **HRSA health center site overlay** on every `/area/*` page is off by default and independent of the area layer: its own published release, filters (default: active service-delivery sites), cache, request cancellation, and stale-response guard; area measure/dataset switching never changes it. At broad zoom it shows grid clusters labeled as display groupings (not service areas) whose counts equal the paged table total; individual points appear at zoom ≥8 with ≤2,000 sites in view, and colocated sites are listed, never merged. Markers use a separate pane so clicks never select area polygons; the table's Details buttons give keyboard access to site detail. The optional **EPA TRI reporting-facility overlay** ("TRI reporting facilities", never "pollution sources") follows the same contract with its own release, cache, and guards and can be shown together with the HRSA overlay (separate panes; panels stack in one right-hand column). It shows one marker per TRIFD; the chemical filter is a facility-level EXISTS test, so several forms for one chemical never produce duplicate markers. Detail lists reported chemicals and form types only, with interpretation notes (reporting does not mean release, violation, risk, or current operation; absence does not mean no pollution). Legacy [main map](../frontend/src/App.jsx) has separate source-specific transitions and caches, including a 10-minute in-memory TTL, request aborts, and in-flight deduplication; its behavior is not the shared area contract. Its geospatial joins can differ from the newer isolated 2024 boundaries.

**Added 2026-11-15 (map consistency package); live since 23:02Z.** Shared behaviour of every `/area/*` page ([Places2025Pilot.jsx](../frontend/src/pages/Places2025Pilot.jsx)): hovering an area shows the legacy-format tooltip (area, measure, value • period, one source line; skipped on touch pointers); clicking selects it, draws a white-cased Deep Navy outline in its own pane, and lists its value, uncertainty, status, and release under "Selected area" in the legend. There is no click popup. Selection is page state keyed by level and GEOID, so it survives panning, measure changes, and geography switches; Esc or "Clear Selection" removes it. The Map Tools bar has Home, Zoom In, Zoom Out, Zoom to selected, Clear Selection, Open profile (county, state, or district; none for tracts), and Base map; it has no "Analyze this area" because the assistant reads legacy tables. The place search and `focus=<level>:<geoid>` both call `GET /api/community/area/{level}/{geoid}` and cap the zoom so the product still draws that level where it publishes it. A selected area whose level is not drawn gets a plain statement and no value. **Colours:** one Blues ramp ([mapColors.js](../frontend/src/branding/mapColors.js)) for every `/area/*` product and for the legacy map's sequential, FEMA rating, and USDA heat scales; status colours are unchanged and non-blue. **Classes:** PLACES, ACS income, AHRF, and CLH use release-wide quintiles from the legend API (`quantile_breaks`), with repeated cut points merged; CMS, USDA, AQI, BRFSS, and ACS community keep fixed registry breaks. A read-only count on staging found the fixed breaks balanced for CMS and USDA but lopsided for EPA `median_aqi` (85% of counties in one class), `p90_aqi` (77%), `days_with_aqi` (81%), and for ACS community poverty, age 65+, and disability at state level (65–75% in the middle class). Changing those breaks edits registry metadata and is a **proposal**, not done.

**Map shapes (2026-11-15).** Map queries no longer simplify each polygon on its own, which left gaps and overlaps between counties when zoomed in. [geometry_sql.py](../backend/app/geometry_sql.py) snaps every vertex to one grid and drops only exactly collinear points, so shared borders stay identical; it is used by all nine `/api/area/map` paths and the legacy county, tract, state-outline, SVI, ACS, HPSA, USDA, and FEMA shape queries. Both map generations send a grid of about one pixel for the current zoom. Measured on staging for Alabama, Georgia, and North Carolina counties: gap area 0.87 square degrees before, 0 after. The CDC funding and TAGGS state maps keep their own shape handling and were not changed. PostGIS `ST_CoverageSimplify` is not usable here (GEOS 3.9; it needs 3.12). A backend test fails if per-polygon simplification returns to a map query.

**CMS Original Medicare GV** (`/area/cms-gv`) describes only Original Medicare beneficiaries with Part A and Part B (all ages; no Medicare Advantage) and never all residents. Standardized payment is adjusted for geographic payment rates, not inflation, and is not labelled risk-adjusted: the CMS catalog says it is not health-status adjusted, although the methods paper contains a conflicting sentence. Readmissions use index admissions as the denominator. Fixed registry display classes are shared across levels for rates. The legend shows the CMS national value as reference only, and suppressed, missing, not-published (DC and PR counties), and zero values stay distinct. The main-map "CMS Medicare Fee-for-Service (legacy import, through 2023)" option is the older, unpinned integration.

**USDA Food Environment Atlas** (`/area/usda-fea`) shows only county values, at every zoom, because USDA publishes no state value for the five selected measures. A national-view message says so, a tract-zoom message says no tract values exist, and the API rejects state or tract requests with 400. Each measure displays its own observation year, definition, denominator, and unit. The low-income measure's denominator is all residents. Fixed registry display classes are used, with published zero, not available (`-9999`/N/A), did not exist (`-8888`), Connecticut planning region (`boundary_not_comparable`), and Puerto Rico (`not_covered`) kept distinct. The page avoids "food desert" labels and says these are historical indicators, not store directories.

The optional **CMS nursing-home overlay** is off by default and independent of all area and other point products. It uses one published CCN row per facility, retains leading zeroes, and keeps distinct facilities at shared coordinates. Only valid published address coordinates with a blank geocoding footnote are mapped; CMS footnote 22 identifies ZIP-based coordinates that are retained but excluded. The table and detail show provider and ownership types, federally certified beds, all four CMS star ratings and their footnotes, processing date, and an official Care Compare link. The explicit unrated filter and text star labels distinguish absent ratings from zero. Map clusters and table use the same release, viewport, and filters, with a 2,000-point cap and 3,000-cluster cap (413 rather than truncation). Certified beds are not vacancies; ratings are not a live care assessment and are never averaged. [CMS guide](../backend/docs/chip_cms_nursing_homes.md) has the source, release digests, and commands.
