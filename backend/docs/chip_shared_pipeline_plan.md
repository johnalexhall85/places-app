# CHIP shared federal-data pipeline and area-map plan

**Planning date:** 2026-11-13. This is an implementation plan, not an implementation. Verified repository and source facts are in [the current-state audit](chip_federal_data_current_state_audit.md); spreadsheet records and preliminary tiers are in [the source inventory](chip_source_inventory.csv). Unknowns stay explicit in the registry until verified. All new structures below are **proposed**.

## Decisions grounded in the audit

- Keep the FastAPI/PostGIS/React deployment and Alembic. A 2-vCPU/7.7-GiB VM can handle a bounded county pilot; no queue, object store, Kubernetes, or tile service is justified yet. Use a dedicated non-web ingestion process and a systemd timer only after one manual release is proven. Avoid overlapping jobs with a PostgreSQL advisory lock.
- Reuse county/tract/state boundaries, bbox and simplification SQL, `App.jsx` abort/request-ID/caching patterns, source-specific legends, and CDC funding's checksum/manifest/transactional replacement design. Keep funding profiles, classifications, filters, access middleware, branding, and existing dataset routes intact. General area observations should not alter `cdc_funding` or funding-model tables.
- Introduce a **release key** in actual observations. Current PLACES `etl_places_release` is an audit log, but facts are keyed by observation year/geography/measure and can be overwritten across releases. A new active-release pointer is necessary for safe publication and rollback.
- Treat the spreadsheet as a catalog, not as 72 ready-to-ingest datasets. Prioritize official county/tract products. State/national-only sources remain cataloged; point sources remain cataloged until area maps work. The CSV distinguishes parent portals and named products and marks unverified facts explicitly.

## Proposed data and process contract

### 1. Registry and adapters

Add version-controlled `backend/app/area_registry/datasets/*.yaml` or JSON records. One product/version family per record, not one federal portal. Required fields: immutable dataset ID; federal publisher and distributor; official landing page; source endpoint/discovery rule; adapter class; supported geography and boundary vintage per level; measure IDs/labels/units; population and denominator definitions; source observation period; release label; valid filters and geography-specific availability; suppression/missing codes; uncertainty fields; allowed aggregation methods (default **none**); release freshness and review policy; license/attribution; source lineage to avoid duplicate measures. Validate registry schema at CI/startup; unknown configuration fails closed.

Each adapter implements `discover_release()`, `fetch_to_archive()`, `inspect_schema()`, `parse_batches()`, `validate_domain()`. A product-specific adapter can write a product table; the shared contract does not force facility records, multi-column CMS facts, funding transactions, or indexes into one generic scalar table. A shared **area observation** table is suitable for the first scalar published estimates, with nullable value and explicit status; product-specific tables can expose a compatible read view later. Keep original product lineage in the catalog. Federal provenance and actual third-party distributor are separate fields.

### 2. Release storage, retrieval, and run control

Proposed migration creates `ingest.dataset_release` (dataset, publisher release ID, observed/issued dates, retrieval date, schema hash, content hash, status, expected geography/measure counts), `ingest.source_file` (immutable path, original URL, ETag/Last-Modified, SHA-256, bytes, retrieved timestamp), `ingest.run` (step, start/end/status/error/attempt, operator or timer), `ingest.validation_result` (named check, observed/threshold, pass/hold), and `ingest.active_release` (one pointer per dataset/product). Make `(dataset_id, publisher_release_id, content_sha256)` unique: the same label with changed bytes is a revised candidate requiring review, not silently “already loaded.” `source_file` paths use `data/ingest/<dataset>/<release>/<checksum>/`; preserve originals and a small manifest, never rename a modified source as the same file.

Downloader: connect/read timeouts, bounded retries with exponential backoff and jitter for 429/5xx, respect `Retry-After`, conservative concurrency (one source download at a time on this VM), API pagination with deterministic sort and page/row counts, per-host rate budget, `.part` temp files plus resume only when source supports Range/ETag; otherwise restart safely. Check free disk before fetch and stage, cap memory/chunk size, maintain run status and idempotent page progress. Record publisher date, observation period, and retrieval time separately. Save response metadata; a successful landing page is not proof an API/download works. Do not download full national data during the audit; implementation will fetch only the selected pilot product.

Use a separate `flock`/PostgreSQL advisory lock by dataset. Staging rows are keyed by candidate release and ingest run. Resume failed download/parsing without touching active data. Validation and publication happen in one DB transaction: mark candidate `published`, atomically switch `active_release`, and commit. Failed or held runs leave the previous active release and its API responses intact. Rollback is an active-pointer switch to a retained published release. New datasets and unexpected schemas always hold for review; established sources may auto-publish only after all expected checks pass and no material drift. The timer invokes a CLI, never a web request.

### 3. Transformation and validation

Canonical geography key is `(level, GEOID, boundary_vintage)` with exact zero-padded FIPS/tract IDs and a boundary source/version table. Do not join USPS ZIP to ZCTA or map 2010 tracts to 2020 polygons without an approved crosswalk; mismatches fail map-readiness validation. Store released source values with units, value type, numerator/denominator when published, population universe, age adjustment, CI/MOE and footnotes, quality status (`observed`, `true_zero`, `missing`, `suppressed`, `not_published`, `invalid`), original source fields, and release/observation periods. Never substitute state values into counties or county values into tracts. Default aggregation is **none**. Only an explicitly documented additive count with complete compatible coverage and a declared method may be aggregated; percentages, rates, medians, and ranks/index scores are never averaged.

Validation gate per dataset/measure/level/period: required and unexpected columns; type/range checks; uniqueness of `(release, level, GEOID, measure, period, population/value_type)`; expected record and non-null coverage bands; FIPS lengths; valid boundary joins; no duplicate source pages; CI bounds/order; denominator/nonnegative checks; suppression encoding; representative source-to-target sample comparison; changed row count/coverage/value distribution versus active release; availability matrix and whether enough valid geometries exist for map publication. Set hard failures for missing required fields/duplicate keys/invalid joins; review holds for unexpected drift or new measure/schema. A loaded release is **not** map-ready until geometry and UI metadata checks pass. Logs expose run ID, step, freshness, errors, and review reason without credentials.

### 4. Retention and operational limits

Retain at least active plus immediately previous published release and all run manifests/checksums; keep failed candidate files only through a defined review window (propose 30 days, subject to PM policy). Never delete a source file referenced by a published release. Publish disk-use metrics and a high-watermark alert before archive growth; keep no more than one full candidate and one staging copy in progress on the 302-GiB-free root volume. Revisit partitioning or external storage only if measured sizes/query times demand it. Keep larger SVI/tract processing chunked; optional precomputed simplified geometry or tiles require benchmark evidence.

## Shared API and map experience

Proposed endpoints under `/api/area`: `GET /datasets` (active products and level/measure/period availability), `GET /datasets/{id}/measures`, `GET /datasets/{id}/releases`, `GET /map?dataset_id&measure_id&period&population&value_type&level&bbox&limit`, `GET /legend` with exactly the same selection, and `GET /table` paginated for accessible display. Internal release/run/validation status is admin-only. The map endpoint returns release ID, observation period, geography level, boundary vintage, units, status, uncertainty, feature count/truncation, and explicit availability reason. Require a bounded viewport for county/tract. Cache keys include active release ID, measure, period, population/value type, level, bbox and simplification. Publish catalog metadata first; frontend discovers permitted combinations instead of inventing years.

The frontend keeps one selection object `{dataset, measure, period, population, valueType, release}` across zoom changes. It chooses the **highest detail level with a published, valid estimate for that exact combination**: default zoom 4 state if available, otherwise county; around zoom 6 county; around zoom 10 tract if available, otherwise county. These are configurable starting thresholds based on `App.jsx:278,308–311,3399–3413`, not fixed policy. A geography transition never changes measure/year/population behind the user's back. If the selected combination lacks that level, keep the prior valid level and show “County estimates remain displayed; no tract estimate is published for this measure and period.” If no valid level exists, show an empty map with a reason and available choices. Do not make a false state layer for PLACES.

Label active geography, source release and observation period directly. Recompute legend from the displayed level/selection and show a loading state while changing layers. Zero gets a numeric color/label; missing gets neutral hatch; suppressed gets a distinct hatch and explanation; not-published/unavailable gets outline/no fill; uncertainty is shown in tooltip/details with measure-specific units. Never interpret absence of a polygon as zero. Add a keyboard-accessible paginated table of the same visible features, with download only after scope/volume review. Reuse boundary geometries independently from values where practical; first measure payload size and redraw time before choosing vector tiles. Keep abort and request-ID guards so old responses cannot replace a new selection. Point/facility layer metadata can be registered now, but point rendering waits until area pipeline acceptance.

## Bounded implementation phases

### Phase 1 — official PLACES 2025 county vertical slice

**Scope:** Select two documented county measures (`dental_crudeprev`, 2022 observation, and `access2_crudeprev`, 2023 observation) from the verified GIS-friendly 2025 source. Build one product registry entry, a Socrata adapter, archive and checksum manifest, release/run/validation tables, candidate staging, scalar area observations keyed by release, active pointer, CLI ingest, read-only catalog/map/legend/table APIs, and a separate “PLACES 2025 pilot” map choice. The map starts with counties; it explicitly says PLACES has no verified state layer. Preserve existing PLACES and funding routes. A first release uses operator review; later unchanged-schema routine releases may auto-publish only after gate approval. Implement paginated deterministic retrieval and verify page completeness; do not assume the one-row sample proves pagination.

**Dependencies/files:** CDC source metadata and API, existing 2023 county boundary; new Alembic revision, `backend/app/area_registry/`, `backend/app/area_ingest/`, `backend/app/routers/area.py`, `backend/scripts/ingest_area_release.py`, `frontend/src/api/area.js`, a small registry-driven branch/component in `frontend/src/App.jsx`, and operator docs. Respect `backend/app/demo_access/middleware.py` and nginx route prefix conventions.

**Validation/tests:** unit tests for wide-to-long mapping, 2022 versus 2023 periods, CI parsing, `0` versus missing, revised bytes under same release label; a small official sample fixture; DB integration tests for duplicate prevention, invalid boundary hold, failed candidate preserving old pointer, and rollback; API tests for bbox caps, exact selection and 401 behavior; browser smoke of authenticated county map and accessible table. Check selected CDC row count against source metadata and exact FIPS coverage; explicitly allow documented KY/PA missing 2023 measures without substituting 2022. Test new code in isolation from existing funding controls.

**Acceptance:** A fresh command downloads and archives the official 2025 county dataset; checksum/source URL/timestamps/release/observation periods are recorded; validated selected observations are published atomically; a map and table show actual county values with accurate missing/CI semantics; repeat run makes no duplicate records; a corrupt or revised candidate leaves prior map working. No older integration or access behavior regresses.

**Deployment/rollback:** Apply additive migration; run one supervised ingest; inspect validation report; switch active pointer only after acceptance; deploy frontend/API; rollback by reverting active pointer and deployment while leaving old tables untouched. Principal risks: changed Socrata wide schema, incomplete pagination, 2023 county boundary join and zero-versus-absent encoding. Decision: confirm two pilot measures and release policy; this plan supplies safe defaults if no preference is given.

### Phase 2 — PLACES tract and geography fallback

**Scope:** Verify exact official 2025 tract endpoint and format; ingest the same selected measures/periods into release-keyed tract observations with 2020 boundary matching. Add county→tract switch at configurable zoom and retain county where tract measure/period is unavailable. **Dependencies/files:** adapter extension, tract validation, same area API, App map branch. **Migration:** only indexes or vintage metadata if needed. **Tests:** viewport caps, multi-state/Connecticut geometry joins, missing tract fallback, unchanged selections, stale request handling, CI and table parity. **Acceptance:** county/tract views use published observations with no fabricated aggregation; unavailable levels explain why. **Deploy/rollback:** publish tract level after validation; disable its registry availability and revert pointer if needed. Risk: tract volume and boundary vintage drift; benchmark on 2 vCPU before tuning.

### Phase 3 — published state→county→tract via ACS 5-year

**Scope:** Select one documented ACS 2020–2024 detailed-table measure with a consistent published state/county/tract definition and MOE; implement Census adapter and geography-specific availability, then demonstrate all transitions. **Dependencies/files:** Census API key or official bulk-file source, ACS registry/adapter, area API/legend/table and App transitions. **Migration:** source-specific ACS staging/observation fields for estimate and MOE, not a rewrite of legacy ACS NMF. **Tests:** exact published values at each level, annotation/suppression, MOE, denominator, boundary joins, 401, fallback, and no geographic imputation. **Acceptance:** all three levels display independently published values for one identical measure/period/population selection. **Deploy/rollback:** additive and active-pointer switch. Risks: key access, ACS annotations and changed table IDs; choose the table before coding.

### Phase 4 — second source, scheduling and operations

**Scope:** Adapt CMS GV or SVI using the shared controls without replacing existing public routes; add CLI status/report, systemd timer with lock, freshness alerts, retention cleanup with dry-run, review workflow. Catalog point datasets but do not render them yet. **Dependencies/files:** adapter, systemd timer/service, operator docs, registry/API metadata. **Migration:** source-specific staging and indexes only. **Tests:** interrupted download resume/restart, 429 retry, schema drift review hold, concurrent lock, retention protections, inactive release rollback, existing funding regression smoke. **Acceptance:** routine known update auto-publishes only after validation, unknown schema/new source needs review, failed refresh keeps old release, disk/resource guard works. **Deploy/rollback:** timer disabled until supervised trial; disable timer and restore active pointer if errors. Risk: source endpoint volatility and archive growth.
